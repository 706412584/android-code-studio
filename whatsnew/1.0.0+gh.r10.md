## Overview

本版本是**性能与稳定性修复版**：修复三个会导致应用卡死的严重缺陷，以及若干
用户报告的可用性问题。如果你遇到过「AI 助手开着时手机发烫、掉帧」「网络错误重试
时应用卡死」「长会话报 400 上下文超限后无法继续」「局域网模型拉不到列表」——
这个版本就是为你准备的。

---

## 主要改动

### 修复：AI 助手面板持续重组（CPU 100%、发烫、掉帧）

1. **markdown 渲染无限重组**。第三方 markdown 库（0.33.0）的已知缺陷：其
   `rememberMarkdownState` 内部有三个对象每次重组都新建、且互不相等，导致
   `remember` 判定永远失效 → 反复重建解析状态 → 无限自激循环。
   实测：主线程 80-100% CPU 持续占用、每 2.6 秒 GC 回收 26MB、10 秒渲染 421 帧
   其中 92% 掉帧——即使**没有任何操作**也在全速空转。上游 0.35 已修，本项目受
   依赖版本约束无法升级，已在调用点复刻修复。
   **修复后：静态时 0 帧（完全静默），滚动 0% 掉帧。**

### 修复：网络错误重试时应用卡死

2. **错误日志写入了完整请求体**。模型请求失败时，诊断日志会把整个请求体
   （含历史消息与图片 base64，可达几十 MB 的单行文本）写进应用内日志视图；
   编辑器的文本测量耗时与该行长度成正比——实测单行 MB 级文本每次测量 1.4 秒，
   而重试期间每次失败都写一条 → 主线程被反复冻结。
   修复：协议层截断日志内容 + 日志视图单行限长双重防线。
   **修复后：重试期间主线程占用从 93% 降到 20%，重试卡片恢复正常消失。**

### 修复：400 context_length 未触发自动压缩

3. **图片未计入上下文估算**。工具结果图片（如文生图）以 base64 随请求发出，
   但本地 token 估算完全不计它们——长会话带着十几张图请求时，服务端报上下文
   超限，而本地一直以为用量很低，压缩机制永不触发。
   修复：图片按张固定估算（对齐 cc-haha 的 image block 估算语义）。

4. **超限错误自动恢复**。此前服务端返回上下文超限时直接把 400 抛给用户，会话
   卡死无法继续。现在会自动收缩历史（保留系统提示词、当前请求与最近轮次）后
   重试一次——对齐 cc-haha 的「检测 → 压缩 → 重试」语义，绝不裸抛。

### 修复：局域网 LLM 无法拉取模型列表

5. **明文 HTTP 策略修复**。网络配置里白名单写的是 `192.168.0.0` / `192.168.1.0`
   ——而 Android 的域名白名单是**主机名精确匹配**（不支持网段），`192.168.1.5`
   这类真实局域网地址根本不匹配，请求被系统在 socket 层拦截。
   表现为「局域网 LLM 死活拉不到模型，手动填写模型名也没用」。
   修复后局域网服务（本地 LLM、局域网网关）正常可用。

### 其他改进

6. **子代理工具调用上限取消**。此前子代理最多 40 次工具调用即被强制中断——
   对「读几十个文件」的调查类任务明显偏小。现改为不限制（30 分钟总时长预算与
   父级取消传播仍然兜底）。
7. **重试卡片流恢复后立即消失**（上个版本的遗留：卡片从失败那刻一直挂到整轮结束）。
8. **新增服务商立即生效**（此前需重启应用才能在助手面板看到）。

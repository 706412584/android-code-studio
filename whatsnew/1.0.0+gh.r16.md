## Overview

本版给 AI 助手补上**跨会话协作**：派遣出去的子代理有了身份与自己的会话，
可以给它追加消息；它停下之后也能带着新消息从原会话续跑。另外修了一条会拖死
主线程的长文本渲染路径。

以前子代理是一次匿名同步调用——派出去、等结论，期间无从干预，也不知道它跑到哪了。
现在每个子代理都有名字、有独立会话（会话抽屉里折在父会话下），父 agent 可以用
`send_message` 给它补一句约束，或者在它停止后唤醒它继续。

全部改动在黑鲨 SKW-A0 / Android 10 上验证。

---

## 跨会话消息（`send_message`）

新增 `send_message` 工具。收件方**没有「忙」这个状态**：消息不会打断它，而是在它
「上一轮工具执行完、下一轮请求发出前」这个安全点被取走（那是唯一不会破坏
tool_use / tool_result 配对的注入位置）。

三段路由：

- 收件方正在跑 → 投进它的注入槽，本轮或下一轮就能看到；
- 收件方空闲 → 进内存信箱，下次该会话运行的开场注入；
- 收件人不存在 → 明确报错，**不会**创建孤儿信箱。

不带 `target` 调用一次会列出当前可投递的对象（会话 + 本会话派出的子代理），
模型不必猜 id。

## 子代理身份与独立会话

- 子代理有了名字（`agent:<名字>` 可寻址），名字是**会话作用域**的——两个会话各自
  可以有一个 `reviewer`，互不覆盖；
- 每个子代理建自己的会话（会话日志与主会话共用同一套存储与折叠），meta 里带
  `parentId` / `subagentType`。主对话仍然干净（隔离性不变），但子代理的过程可回看；
- 会话抽屉把子代理会话折在父会话下（点击父会话行前的箭头展开），不再平铺成一堆
  无名条目。

## 唤醒已停止的子代理

`send_message` 发给 `agent:<名字>` 时，若该子代理已停止，则读它的会话折叠出历史，
把消息当作下一次 prompt **在后台**续跑（复用同一个会话 id，历史才连得上）。
完成后有系统通知——子会话跑在另一个会话 id 上，它的完成事件不进父会话的事件流。

## 工具输出护栏：修长文本卡死主线程

`Text` 的测量成本与**最长那一行**成正比，而不是与总长度成正比。一条几十万字符的
压缩 JSON（没有换行）交给 `Text`，minikin 要一路扫到行尾才能定断点，主线程在首帧里
跑满 CPU 并 ANR。

现在分三段：≤ 32k 原样渲染但单行封顶 4k 字符；> 32k 只渲染**尾部**预览（最后 8k
窗口取 24 行、每行 400 字符）加一个折叠徽标；点「展开」后按 4k 字符 / 40 行分块揭示，
绝不把全文拼回一个字符串。工具结果的有效信息（报错、汇总、退出码）几乎总在末尾，
所以预览取尾部而不是头部。

影子屏的终端 / 浏览器 / 信息三张卡同样接入——那里也是几十万字符的 shell 输出。

## 子代理派遣卡片

`agent` / `agentb_*` / `agentx_*` / `agent_pipeline` 的派遣不再是一个普通工具行，
改渲染成卡片：代理名 + 状态药丸（运行中 / 已完成 / 失败）+ 任务描述 + 步骤摘要 +
结论。折叠态就能看出这次派发在做什么、跑到哪一步。

## 真机抓到并修复

初版续跑把服务商传成了 `null`，`endpointFor(null, null)` 返回 null，于是这次续跑以
「服务商未配置 API 密钥」**静默失败**——工具已经回了「已在后台继续」，而子会话文件
一个字节都不会变。修复方式是显式解析当前服务商与模型（与用户发消息时的同一套来源）。

这个缺陷单元测试抓不到：它需要「服务商偏好为空」与「真实 run() 的前置校验」同时成立。

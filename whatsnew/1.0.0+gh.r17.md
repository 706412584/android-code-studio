## Overview

本版修好 **MCP over HTTP** 的规范符合性。用官方 SDK 写的 MCP server（TypeScript /
Python 默认实现）此前一定连不上，现象是「配置了 server，但工具列表里找不到它」——
两条失败路径都被静默吞成一条错误日志。

顺带说明一个易混淆点：如果添加 server 时没点到「确认」，配置根本不会保存，
表现同样是「找不到工具」。本版把这条也补进了排查提示。

全部改动在黑鲨 SKW-A0 / Android 10 上验证。

---

## MCP over HTTP：两个规范符合性缺陷

`StreamableHttpTransport` 有两处违反 MCP 2025-03-26 的假设，且互相独立：

- **`Accept` 只声明了 `application/json`**。规范要求客户端同时接受
  `application/json` 与 `text/event-stream`；官方 SDK 的实现缺任一类型直接回
  **406 Not Acceptable**。现在改为 `application/json, text/event-stream`。

- **假定响应体一定是裸 JSON**。服务端可以按规范用 `text/event-stream` 回包，
  此时正文是 `event: message` / `data: {...}` 帧。此前把它交给 JSON 解析器必然失败，
  报的是「server 返回的不是 JSON（可能地址填错）」——一句会把排查方向带偏的错误。
  现在按正文首字符判断格式（合法 JSON-RPC 必以 `{` 开头），剥掉 SSE 帧外壳；
  多帧取最后一条 `message` 帧；解析不出 data 行则原样返回，保留原有可读错误。

**为什么这两个缺陷特别难查**：`AgentOrchestrator.registerMcpTools` 对每个 server
的失败都只记一条 `ErrorLog` 然后继续，用户侧只看到「AI 说没有这个工具」，
既看不到 406，也看不到解析失败。这也是为什么最初怀疑是模型幻觉。

## 验证

- 新增 `McpStreamableHttpTransportTest`（6 条），修复前 3 条失败：
  - `acceptHeaderDeclaresBothJsonAndEventStream`
  - `sseFramedResponseIsParsed`
  - `multiLineDataFieldIsJoined`
- `core:ai-tool` 全量测试通过。
- 另用按官方语义严格校验的 mock server（缺任一 Accept 类型即 406）端到端跑通
  `initialize` → `tools/list` → `tools/call`。
- 黑鲨实机：配置一个返回纯 JSON 的 MCP server
  （`http://127.0.0.1:7801/mcp`，协议版本 `2025-06-18`），
  `tool_search` 成功展开全部 6 个 `mcpx_*` 工具。

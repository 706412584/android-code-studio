## Overview

本版修好 AI 助手的**图片附件链路**。此前用户附 3 张图，气泡里只看得到 2 行路径文字、
一张缩略图都没有，而模型实际只收到 1 张——三处断点各丢一部分信息。

现在：发送时把全部图片打包进多模态请求（协议层 payload 从单图扩展为数组），
气泡里渲染横向缩略图条，点任意一张进全屏图集，可左右切换并显示「n / m」计数；
附件元数据随会话落盘，重启应用回看历史时缩略图仍在。

全部改动在黑鲨 SKW-A0 / Android 10 上验证。

---

## 图片附件：三处断点

- **气泡只显示路径文本，没有缩略图**。用户消息的条目模型（`Message`）没有附件字段，
  映射层也不填 `AgentUIMessage.attachments`，因此现成的 `MessageAttachmentList`
  从未被渲染过一次。现在 `Message` 带附件元数据，映射层透传，气泡按类型分流：
  图片走横向缩略图条，其余附件仍走纵向列表。

- **发 3 张只显示 2 张**。`imageRawInputJson` 只取第一张图塞进多模态 payload，
  而 `attachmentContextExcludingImage` 又把这第一张从文本里剔除——于是第 1 张在
  界面上没有任何痕迹，第 2、3 张只剩一行路径，模型实际只看到 1 张。现在 payload
  打包全部可发送图片，两处判定统一走同一个 `sendableImages()`。

- **相册图片的路径模型读不到**。`content://media/picker/...` 的临时授权在选择回调
  结束后即失效，落进正文的路径等于死链。现在选图时把字节落一份到
  `filesDir/ai/attachments/`，交给模型的是能反复读取的真实路径。

## 协议层：多图 payload

- `ImageInputPayload` 新增 `images` 数组，同时仍把第一张写进旧的 `mime_type` /
  `data_base64`——**旧会话日志与未升级的读取端行为完全不变**，这是刻意保留的线格式兼容。
- OpenAI 兼容与 Anthropic 两条序列化路径都输出全部 image block，顺序即用户选择顺序
  （模型按「第一张/第二张」描述时与用户看到的排列一致）。
- 发送侧设三道闸：单条最多 4 张、单张 ≤4MB、合计 ≤12MB。超出的部分降级成路径文本，
  模型仍能自己用 file 工具读——而不是让整条请求被服务端 400 拒绝。

## 全屏图集

- 新增 `showGallery(context, images, startIndex)`：左右箭头 + 「n / m」计数器 + 关闭按钮。
- **切图时重置缩放矩阵**。不重置的话，在第一张上放大到 4x 再切到第二张，第二张会以
  同样的倍率出现在屏幕外——用户看到一片黑，以为图没加载出来。
- 只有一张图时隐藏箭头与计数器：一个永远点不动的箭头比没有更让人困惑。
- 单图入口 `showLightbox` 保留为 `showGallery` 的薄包装，旧调用点不改。

## 会话回放

- `UserMessageEntry` 新增 `attachments` 字段，只存元数据（文件名 / 落盘路径 / MIME /
  大小 / 是否图片），**不存 base64**——图片本体已在磁盘上，日志里再存一份会让 JSONL
  膨胀到几十 MB。
- 无附件时**不写该字段**，日志行与旧版本逐字节一致，便于回滚。
- 旧日志没有这个字段时解析为空列表：历史消息照常显示，只是没有缩略图。

## 顺带清理

- 删除不再被引用的 `dialog_tool_image.xml`（单图灯箱布局已被图集布局取代）。
